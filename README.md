# Agent ID Community Terminal

自己部署、自己连接钱包的 BSC Agent ID 交易终端，覆盖 Four.meme、Flap ID Agent Curve、Gang.fun 的内盘、发行后曲线和已验证外盘。包含实际交易引擎，默认关闭真实下单。

## 新手安装

1. 从 [Node.js 官网](https://nodejs.org/) 安装 **22 或更新的 LTS 版本**，安装后重新打开终端。
2. [下载本仓库 ZIP](https://github.com/MetaverseX24/agent-id-trade-community/archive/refs/heads/main.zip)，解压后进入项目目录。
3. **Windows 双击 `start.cmd`**；macOS/Linux 在该目录运行 `sh start.sh`。首次自动安装锁定版本的依赖，随后打开本机网页。不需要 Git、Docker、私钥或自己改代码。网络受限时安装可能失败，窗口会保留原因。
4. 点“扫码连接”，用自己的币安 App 扫码并核对配对码。需要已领取 Agent ID、有效开发者模式、足够限额、“交易所有代币”及 BNB Gas。
5. 初次默认“仅报价”。准备好后进入“钱包与设置”，勾选真实交易并输入 `ENABLE LIVE`。回到交易页填 CA、选钱包、点买卖。币安仍可能要求 App 确认。

关闭启动窗口或电脑关机，程序和自动转出任务也会停止；要持续运行请自行部署在服务器。服务器启动可用 `sh start.sh --no-open`，电脑通过 SSH 隧道访问：`ssh -L 3000:127.0.0.1:3000 <你的服务器>`，再打开自己的 http://127.0.0.1:3000。主界面仅供单个使用者自托管，不直接向陌生访客开放。

启动器只使用本机安装的 Node/npm，首次按 lockfile 安装依赖并禁用依赖安装脚本；不安装系统服务、不改防火墙或管理员权限。再次启动会复用依赖，lockfile 更新后重新安装。`node scripts/setup.mjs --check` 可仅检查安装，不启动网页或下单。

Windows 启动器和钱包调用会继承使用者已启用的系统 HTTP/HTTPS 代理；其他系统可在启动终端设置自己的 `HTTPS_PROXY` / `HTTP_PROXY`。代理只在本程序进程中使用，本机钱包节点流量默认不走代理。不提供作者的代理或网络凭证。使用代理时需官网最新 LTS，以支持 Node 的环境代理功能。

## 手动运行

需要 Node.js 22 LTS 或更新版本。

```sh
npm ci --ignore-scripts
npm start
```

打开自己设备的 http://127.0.0.1:3000。服务器使用 SSH 隧道：`ssh -L 3000:127.0.0.1:3000 <你的服务器>`。主界面只监听本机，校验来源和 CSRF。本项目是单个使用者的自托管软件，不是直接向陌生访客开放的多租户服务。

初次为“仅报价”。真实交易使用 `npm run live` 启动，在设置页输入 `ENABLE LIVE` 启用，然后扫码连接自己的币安钱包，在官方页面核对配对码。还需 Agent ID、有效开发者模式、足够限额及“交易所有代币”设置。不要提供助记词或私钥。

## 能力

Gang 已适配新版 V3 曲线、公平打新及专用路由，同时兼容旧币。新版 BNB 底池直接通过路由买入；已验证外盘卖出直接收 BNB。打新只支持整份，实际钱包上限可能低于 1%，发射后卖出或转出可能影响后续奖励。[版本与验证细节](docs/gang-20261028.md)。

- CA 统一入口、链上登记识别、阶段/底池/真实路由检查。
- 买入 1%、0.5%、自定义比例或 BNB；卖出 10%、30%、50%、100% 或自定义。默认每钱包最多 0.3 BNB，Gas 另留。
- 多钱包勾选、并发提交、独立预算、预览与结果。三个钱包各买 1% 的默认合计上限为 0.9 BNB，并非合计买 1%。并发不保证同块或全部成交。
- 优先使用现有底池币；缺少部分走已验证的 PancakeSwap V2 直连或稳定币中转，按真实精度计算。
- 单钱包锁、请求查重、App 等待状态、限额授权、回执核对；结果未明阻止补单。
- 换币、限额授权及刷新报价在同一订单中连续完成；首次报价不是预算上限。按本单预算和滑点范围准备价格缓冲，超限时处理本单新换而未使用的底池币，不自动追价或重复买入。
- 新盘列表、平台/阶段/底池/市值筛选、收藏与排序；1 分钟、5 分钟、15 分钟和 1 小时的实际成交 K 线及成交流。
- 持仓与盈亏：已确认成交的加权成本、部分卖出的已实现盈亏、剩余持仓的未实现盈亏、当前可卖估值及累计 Gas。按不同底池币分别统计，不把不同币种直接相加。
- 自填 HTTPS/WSS RPC；留空使用公共 BSC 节点。WSS 用于区块提醒，HTTP 定时更新作为备用。

Flap 份额发行后需领取。外盘只支持已验证路径，缺少流动性、协议升级和未支持路由会报错。卖出所得自动换回原生 BNB：WBNB 解包，其他底池币走币安市价兑换并开启 MEV 保护。只处理本单链上证实的所得；买入后仅退回本单新换而未消耗的底池币，不动原有余额。默认滑点上限 30%；这不是防夹保证。遇到 App 确认会等待，未知提交结果不重复下单。本版不提供后台自动止盈止损，不把价格触发等同于保证净回本。

盈亏历史以本部署保留并核实的成交为基础，链上回执计算退款后的净支出。外部转入、缺失历史、未核实的原生币支出和持仓单位变化会显示成本不全，不伪造零成本盈利。不同报价币不能可靠还原历史汇率时不冒充精确美元收益；Gas 单列。K 线只覆盖实际取得的成交范围，不能保证完整历史。

钱包节点的领取／转出操作接口只在管理员显式设置 `AGENT_PRIVATE_OPERATIONS=1` 时可用，并且还需钱包节点连接密钥；默认关闭；公开页面的发射后自动转出使用单独的逐笔选择，不预置收款地址，不启用私人止盈规则。

## 发射到外盘后自动转出

买入时勾选“发射到外盘后自动转出”，填写自己的 BSC 收款地址，再点击买入。默认关闭，每个钱包、每个币单独记录；收款地址先加入币安 App 地址簿。只有买入成交后，才监控这个钱包的这枚币；平台链上状态确认进入外盘后，转出届时该钱包的全部剩余代币。Flap 有待领取份额时先领取，再转出真实代币。不是看到页面进度 100% 就立即转。若买入的已经是外盘币，勾选后会在买入成交后尝试转出。

在“我的持仓”底部查看任务、收款地址和转出回执，可关闭后续自动转出。新买入不勾选时会关闭该币旧的未提交规则；已经提交的转账无法靠关闭按钮撤回。任务、收款地址和请求编号保存在本部署的 data/；未知提交先核对，不能重复转账。重启后继续监控未触发的规则；中断或失败的执行显示需要处理，已完成的转账核对回执后结束。币安要求 App 验证时仍需本人操作，地址簿、开发者模式、余额和 Gas 限制仍适用。

每个钱包节点监控自己的会话，多钱包节点需一起更新到本版。自动规则依赖程序持续运行和可用 RPC；不保证恰好在发射同一秒转出，也不能绕过代币锁定或币安限制。不转出 BNB 或其他币，不附带维护者的收款地址、服务器或付费 RPC。

## 多钱包，不用 Docker

Linux 管理员可用独立用户、网络环境和会话目录运行第二钱包。安装器只安装 Ubuntu 官方的 slirp4netns，创建 systemd 服务和本机 Unix socket，不开公网端口，不改防火墙/IP 转发。主服务无需 root 权限。使用 Node 22，项目路径不要包含空格；owner/group 填主界面使用者：

```sh
sudo /path/to/node scripts/add-wallet-linux.mjs --id=wallet2 --label=第二钱包 --owner=youruser --group=yourgroup --profiles=/absolute/path/project/data/wallet-profiles.json
```

没有执行中订单时重启主界面，分别扫码连接。每钱包连接自己的合法账户，仍受币安规则限制。不要复制会话或在同目录覆盖登录。可选 Docker 部署见 Dockerfile 和 `npm run wallet:add -- --id=wallet2 --port=4332`，端口仅发布本机。

## RPC、费用与隐私

读取、报价、行情发现及回执依赖 RPC，公共节点可能限流。自填 RPC 不能改变币安签名/广播或 App 确认要求。行情来自平台接口和链上，可能缺失或延迟，列表不是完整索引。

部署者支付自己的服务器、RPC 和链上费用。仓库不提供作者服务器/付费 RPC，不含个人站点、钱包会话、收款地址或凭证。`data/`、`.env` 和会话/连接密钥已忽略，保存在自己部署中，不要打包分享。

点击买卖即授权该单限额内的必要换币、限额授权、领取与交易。队列逐步检查预览、目标、钱包、spender 和累计原生币支出后自动连续执行，不再逐步点网页确认；未知风险、权限变化、无限额授权或超出范围会停止。链上仍可能是多笔，不能保证同块或原子成功。币安要求 App 验证时，使用者仍需自行处理。超时不自动重买；重启后未核实订单保持阻塞，先查 App/链上记录，再处理本机状态，不能删除订单直接补单。

最近 5 秒内由本部署队列核实的钱包状态可用于同单预检，过期或身份不符会重新查询；合约模拟和签名要求仍逐笔执行。已知交易哈希的回执在最初 5 秒每 150ms 查询，随后降低频率，150ms 不是成交承诺。

过期的手机确认不会永久占住订单：超过币安确认时限及缓冲期后，程序核对完整交易记录、回执、钱包身份、锁状态及链上 nonce，仅在证实未广播时关闭旧请求。未知提交、仍待上链的交易和已经成交但换回 BNB 未完成的订单不会被当成可重复下单。关闭旧请求不自动补单。

## 代码与检查

`public/` 是独立设计的终端；`src/jobs.mjs` 为多钱包队列；`src/engine/` 为三平台执行、预览与回执；`src/market.mjs` 为只读行情；`skill/SKILL.md` 是交易工作流。保留早期只读/演示模块，实际下单入口为 `/api/orders`。

`npm test` 覆盖限额、并发锁、失败隔离、幂等、超时核对、来源校验与行情计算，不真实下单。AGPL-3.0，依赖保留各自许可证。本项目尚未经过第三方安全审计。
