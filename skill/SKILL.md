# Agent ID 交易

没有用户约定，不把单独 CA 当成买入指令，不复用他人预算或钱包。买入需金额/目标及每钱包上限；卖出需比例。网页与聊天统一提交本部署的 /api/orders，不另起绕过队列的下单脚本。

读取 /api/wallets 核对连接、地址、Agent ID、开发者模式及有效期。只用用户选择的钱包，默认 primary，不默认全选。walletIds 是分别执行，各钱包独立预算/目标；展示合计上限，不承诺同块或原子成交。不同钱包各自扫码，不能复制会话。

由队列从链上识别平台、阶段和真实池。Four 核对 Agent ID 模板；Flap 区分份额内盘、已发行曲线和外盘，发行后先领取；Gang 核对具体 Launchpad、底池币及精度。名称、后缀不能代替登记证明。

每次意图使用随机 UUID requestId，同一次操作查询和重试沿用原编号。订单参数示例仅供格式参考，不是授权：

```json
{"requestId":"11111111-1111-4111-8111-111111111111","walletIds":["primary"],"token":"<完整CA>","action":"buy","mode":"percent","bps":100,"budgetBNB":"0.3"}
```

bps=100 为总量 1%，卖出 bps=10000 为当前持仓全部；按金额买用 mode=bnb。不能自动放宽设置页每钱包上限。公开版没有个人默认交易授权。

操作接口使用本部署 data/api-token.json 的本机 token，或页面同源 CSRF，不公开密钥/二维码参数/会话。远程使用 SSH 隧道，不将单用户入口直接开放给陌生人。

一次明确买卖授权覆盖本单必要的换币、限额授权、领取与最终交易。队列建立 workflowConsent，逐步核对钱包、协议目标、动作、spender、累计原生币上限和 Binance 模拟后连续执行，无需逐步调用 /api/approve。不得为自动执行而放宽订单参数、使用无限额授权、忽略未知风险、模拟失败或权限变化。requireConfirmation=true 仍由用户在币安 App 操作；链上可能多笔，不宣称原子捆绑。

默认滑点上限 30%，具体采用部署设置。已有底池币和剩余授权额度足够时复用；换币、授权后重新报价目标。卖出所得及买入时本单新换而未使用的底池币自动换回原生 BNB，原有余额不顺带兑换。WBNB 按本单证明数量解包，其他底池币走币安市价单并开启 MEV 保护；自定义内盘调用没有同等开关，不能保证防夹。只有订单终态及链上回执核对通过才报告兑换完成；部分成交、未知提交和 App 待确认均不重发原单。

以 /api/orders 每钱包状态及回执为准，区分仅报价、待网页确认、待 App、已广播、已成交、结果不明。超时/重启后先核对，禁止补单。按当前状态复核合约权限、重入防护、升级、真实池和兑换路径，登记不等于安全保证。

手机确认超过 5 分钟及 30 秒缓冲后，由队列核对完整历史、钱包身份、回执、交易锁和 pending/latest nonce，只有证实请求过期且未广播才解除旧记录。不得仅按超时时间、无 txHash 或页面失败就删状态重发；旧请求关闭不代表已经成交，也不自动执行失败的历史点击。

RPC 留空走公共节点，配置自己的 HTTPS/WSS，不使用维护者私有节点。登录及连接密钥仅留在本部署 data/，不提交 Git。本版没有自动止盈止损/转出，不把参考项目的功能误报为已实现。

看盘用 `/api/market`、`/api/detail?token=<CA>&interval=1m|5m|15m|1h`，收藏保存在本部署。持仓和盈亏用 `/api/portfolio?walletId=<ID>`；只读接口不下单。成本、已实现和未实现收益按各底池币单位展示，Gas 单列。`basisComplete=false` 不能当成零成本盈利，不能据此擅自启动自动卖出；市值或页面单价也不代表整仓实际可兑金额。
